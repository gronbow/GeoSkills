# GeoSkills v0.8 候选版综合审查

审查日期：2026-08-31

## 结论

GeoSkills 当前不是独立 Web 应用，主要用户界面是 Codex Skill、命令行提示和 GitHub 项目页。因此，本轮把安全边界、投稿图最终尺寸和项目首页作为最高优先级，没有改动标准化值、TAS 边界或 K2O-SiO2 边界。

## 本轮已完成

- 增加 89 × 75 mm、600 dpi 单栏投稿预设；长文献说明进入报告，不挤占图内数据区域。
- 对单栏蛛网图和 Harker 图设置最终尺寸密度门禁，避免生成不可读图件。
- 在本地可复现 CSV 导出前检查电子表格公式注入风险，只报告计数，不暴露标签。
- 增加每周和依赖变更时运行的 Python 依赖漏洞审计。
- 增加安全报告说明、Skill 图标、品牌色、六类合成数据图廊和功能矩阵。
- 明确注册表中不同隐私模式是否包含绘图源数据。

## 验收结果

- 完整自动测试：283 项通过，1 项按设计跳过。
- Skill 结构、Python 编译、开发环境自检：通过。
- 依赖漏洞审计：未发现已知漏洞。
- 六类双栏图和六类单栏图均完成 SVG、PDF、TIFF、PNG 端到端生成。
- 12 份可分享任务包均未保留源数据 CSV，隐私令牌扫描无命中。
- 最终尺寸视觉复核发现并修复了单栏 REE/蛛网图纵轴标题裁切。

自动检查不能替代地球化学专业复核或投稿前人工视觉复核。K2O-SiO2 合成示例仍按设计返回“需要科学复核”，不是技术失败。

## 合并前仍需人工决定

以下是 GitHub 仓库设置，不应由本地候选版自动修改：

1. 为 `main` 启用分支保护或规则集，要求测试和依赖审计通过后才能合并。
2. 启用 Dependabot 漏洞提醒和安全更新。
3. 启用私密漏洞报告；确认公开 issue 模板不会诱导用户上传研究数据。
4. 决定 v0.8 是接在 v0.7 PR 合并后再提交，还是建立堆叠 PR；不得把 v0.8 直接合入仍停留在 v0.6 的 `main`。

## 后续优先路线

### P1：可维护性与性能

- 把配方验证、检查器和绘图器的硬编码分支逐步收敛到一个可执行注册表。
- 避免同一规范化临时表在多任务计划中被重复读取；增加有上限的内存缓存和读取次数测试。
- 为跨 Windows/Linux、Python 3.11/3.12 的依赖锁定与发布 SBOM 设计可复现流程。

### P2：普通用户交互

- 增加逐步配方向导：选择文件、工作表、列映射、图件和输出模式，再生成 YAML。
- 为常见错误提供更短的用户提示，同时把技术细节留在 QA 报告。
- 如果开发独立 Web 界面，默认只启动本机服务，不把数据上传第三方；先完成威胁模型、文件生命周期和浏览器隔离设计。

### P3：新增科学图件

- 新分类图继续遵守“原始边界数值、文献出处、版本哈希、专业复核、边界点策略”五项门禁。
- Sr-Nd 同位素图可先开发无分类边界的坐标模式；初始比值、年龄校正或演化线必须另立科学规格。
- Zr/TiO2-Nb/Y 仅在取得可核验的原始边界数值并完成专业复核后注册。
